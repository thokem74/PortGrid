# Domain docs

PortGrid uses a single context. Before exploring the codebase, read the root `GLOSSARY.md` and the architecture decision records in `docs/adr/` that apply to the task. If either location is absent, continue with the available sources. Use the domain-modeling skill to record terminology and decisions as they are resolved.

Use glossary terms in issues, proposals, hypotheses, and tests. When a domain term is missing, check the vocabulary already used in the project and flag any gap for domain modeling.

If a proposal conflicts with an ADR, identify the ADR and explain why the decision should be revisited.
